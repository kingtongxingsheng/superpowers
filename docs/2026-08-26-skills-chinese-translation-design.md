# 技能目录中文化设计

## 背景

将 `skills/` 目录下现有技能及其配套文档中的人类可读内容翻译为中文，便于中文工作流使用，同时保持技能系统的机器可读契约、触发机制和可执行资源不变。

## 范围

- 覆盖 `skills/` 下所有文件。
- Markdown、提示模板、示例文档和测试说明中的自然语言全部翻译为中文。
- 脚本、示例代码和 Graphviz/DOT 文件只翻译明确不会改变行为的注释及用户可见说明；可执行语句、字符串协议、命令、路径、正则和标识符保持原样。

## 不可修改内容

- 技能目录名、技能名以及交叉引用中的技能标识。
- YAML frontmatter 的字段名及其机器契约；`name` 保持原值。
- 工具名、命令名、参数名、文件路径、URL、环境变量、代码标识符、JSON key、断言标识和协议字段。
- Markdown 代码块中可复制执行的代码，除非仅修改不会影响执行的注释。
- Shell、JavaScript、TypeScript、CJS 和 DOT 的语法与程序逻辑。

## 实施方式

1. 按技能目录分批处理，优先主 `SKILL.md`，再处理配套文档。
2. 保持原有章节结构、列表层级、表格列数、代码块边界和链接目标。
3. 技术术语首次出现时使用中文说明，固定 API、命令和技能名保留英文。
4. 不进行无关重构、不调整行为型内容的语义强度，不改变测试意图。

## 风险与控制

- **触发失效：**保留 frontmatter 的 `name` 和契约字段；检查所有技能主文件的 frontmatter。
- **脚本破坏：**不翻译可执行代码和协议字符串；运行语法检查及仓库测试。
- **链接断裂：**保留相对路径和锚点标识，完成后扫描内部引用。
- **语义漂移：**逐文件对照原文，重点复核强制性规则、例外条件、工具调用格式和测试断言。

## 验证方案

- 检查修改文件清单，确认 `skills/` 下所有目标文件均已处理。
- 对脚本执行 Shell、JavaScript、TypeScript 可用的语法检查。
- 校验 YAML frontmatter、代码块边界、技能名、命令、路径和交叉引用未被改写。
- 运行仓库现有测试；若某项测试依赖外部环境，记录实际阻塞原因。
- 完成中文可读性和关键契约人工复核后再报告完成。
