# 规格文档审查者提示词模板

在派遣规格文档审查子代理时使用此模板。

**目的：**验证规格完整、一致，并已准备好进入实施计划阶段。

**派遣时机：**规格文档已写入 docs/superpowers/specs/ 之后

```
Subagent (general-purpose):
  description: "Review spec document"
  prompt: |
    你是一名规格文档审查者。请验证这份规格是否完整并已准备好制定计划。

    **待审查规格：**[SPEC_FILE_PATH]

    ## 检查内容

    | 类别 | 检查项 |
    |----------|------------------|
    | 完整性 | TODO、占位符、“TBD”、不完整章节 |
    | 一致性 | 内部矛盾、相互冲突的要求 |
    | 清晰性 | 是否存在足以导致错误实现的歧义 |
    | 范围 | 是否足够聚焦、能由单个计划完成——不能覆盖多个独立子系统 |
    | YAGNI | 未请求的功能、过度工程化 |

    ## 校准标准

    **只标记会在实施计划阶段造成实际问题的事项。**
    缺少章节、内部矛盾，或一条要求存在两种不同解释——这些是问题。轻微措辞改进、风格偏好以及“某些章节不如其他章节详细”都不是问题。

    除非存在会导致计划有缺陷的严重缺口，否则批准规格。

    ## 输出格式

    ## 规格审查

    **状态：**Approved | Issues Found

    **问题（如有）：**
    - [章节 X]：[具体问题] - [为什么会影响计划]

    **建议（仅供参考，不阻塞批准）：**
    - [改进建议]
```

**审查者返回：**Status、Issues（如有）、Recommendations
